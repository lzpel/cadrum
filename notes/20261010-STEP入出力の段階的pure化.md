# STEP入出力の段階的pure化

STEP入出力を先に切り出せば、全面移植を待たずに OCCT のビルド対象を減らせる。

- 段階A（C++のみ）: 色付きSTEPを XCAF 文書経由から `STEPControl_Writer/Reader` + `STEPConstruct_Styles` に置き換える。`STEPConstruct_Styles` は XCAF に依存しない。
- 段階Aの効果: TKXCAF と ApplicationFramework（TKBin, TKLCAF, TKCAF, TKCDF）を `OCC_LIBS` から外せる。TKDESTEP の EXTERNLIB と STEPCAFControl をパッチで外せばビルド対象からも消える。
- 段階B（Rust）: C++ は平らなトポロジー・幾何を書き出すだけにし、STEPエンティティの生成と出力を Rust で行う。前処理の ShapeProcess は C++ に残す。
- 段階Bは Writer を先に作る。同じ入力を OCCT 版でも書けるので、ビット単位の一致を `cargo test` で検証できる。Reader は BRep の再構築と修復が要るので後回しにする。
- 段階B完了で TKDESTEP・TKXSBase・TKDE・TKDECascade も外れ、段階Aと合わせ9ツールキット・約50万行がビルドから消える。
- 段階Aは pure と無関係なので main から別ブランチで進める。
